# 棚の空き状況の更新

編集するファイルは `shelf-availability.json` です。公開用の状態だけを記録し、委託者名・連絡先などは入力しません。

## ローカル管理画面

作業フォルダ直下の「棚の空き状況を管理.cmd」をダブルクリックすると、PC内の管理サーバーを起動してブラウザを開きます。URLは `http://127.0.0.1:8787/` です。Node.jsを使用し、外部ネットワークから接続できないよう127.0.0.1で待ち受けます。

1. 3Dの棚または棚名ボタンで、編集する棚を選びます。
2. ①〜⑯をそれぞれ「空きあり・利用中・確認中」に変更します。一括変更もできます。
3. 面の変更時には日本時間の今日が確認日に入ります。必要に応じて日付を修正します。
4. 「ローカル保存」、または「保存してGitにコミット」を押します。
5. 公開する場合は、未送信コミット件数を確認し「GitHubへプッシュ（公開）」を押します。
6. 終了時は「管理画面を終了」を押します。

コミットには空き状況ファイルだけを含めます。ほかのステージ済みファイルは含めません。プッシュはmainブランチの未送信コミットを全て送るため、ほかの作業のコミットがある場合は内容を確認してください。

管理画面のコード（`local-admin/`）と起動用cmdはGit対象外のローカルファイルです。GitHub・公開サイトには含めません。別PCへ移すときは、このフォルダとcmdを別途コピーしてください。

## 面ごとの状態と集計

管理画面で保存すると、各棚に `faces` が追加されます。キーは `"1"`〜`"16"`、値は `"空きあり"`・`"利用中"`・`"確認中"` です。16面すべてを登録します。

- 確認中が1面でもある：棚全体は「確認中」。
- 16面すべて空きあり：棚全体は「空きあり」。
- 16面すべて利用中：棚全体は「満室」。
- それ以外：棚全体は「一部利用中」。

`status` はこの集計と一致する必要があります。面を確認した記録がある場合は `updatedAt` が必須です。公開ページには面数の内訳も表示されます。旧形式の棚全体だけの記録も読み込めますが、「一部利用中」から個別の使用面は推測しません。

右からの並びは大型棚A・大型棚B・小型棚A・小型棚B・小型棚Cです。画面の左から見ると小型棚C・小型棚B・小型棚A・大型棚B・大型棚Aです。各行の `id` は変更せず、`status` と `updatedAt` を編集してください。

| id | 棚 |
| --- | --- |
| large-a | 大型棚A |
| large-b | 大型棚B |
| small-a | 小型棚A |
| small-b | 小型棚B |
| small-c | 小型棚C |

状態は次の4種類です。

- `空きあり`：棚全体が未使用。
- `一部利用中`：一部の面が利用中。
- `満室`：貸出可能な面に空きがない。
- `確認中`：最新状況を確認中。

`updatedAt` は、その棚の状況を確認した日本時間の日付を `YYYY-MM-DD` で入力します。例：`"updatedAt": "2026-11-09"`。確認実績がないときだけ `null`（引用符なし）にします。`確認中` 以外の状態には更新日が必須です。

更新の手順：

1. 対象の棚の状態・更新日を編集して保存。
2. リポジトリのルートで `node --test akiba_audio_parts/tests/shelf-availability.test.mjs` を実行。
3. 差分を確認し、Gitにコミットして `main` へプッシュ。
4. Cloudflareのデプロイ完了後、公開ページの状態・更新日を確認。

会話で「大型棚Aを一部利用中に、更新日を今日にして」のように指示しても更新できます。状態データに不備がある、または取得できない場合は、サイトでは全棚を「確認中・未更新」として表示します。

この表示は予約受付・契約管理システムではありません。実際の契約記録と照合して更新してください。
